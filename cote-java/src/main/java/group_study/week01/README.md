# 1주차

## ⭐ 다리를 지나는 트럭

[문제 풀이](./ex01_truck_crossing_bridge/Solution.java)

[테스트 케이스](../../../../test/java/group_study/week01/ex01_truck_crossing_bridge/SolutionTest.java)

### 접근 방법 및 시도
- 트럭 한 대가 다리를 건너는 시간이 안 나와 있었으나, 최대 `bridge_length` 대만큼 다리에 올라가 있을 수 있다는 조건에서 다리의 길이를 변수명인 `bridge_length`으로 간주하고 1초에 1만큼 다리를 건넌다고 생각하였다.
- 처음에는 트럭의 진입 순서를 직접 결정하여 최단 시간이라는 최적해를 구하는 그리디 문제로 생각하였으나, 트럭의 진입 순서가 정해져 있었다는 점에서 큐 사용을 고려하였다.

### 아이디어 및 풀이
- 매 초마다 다리 위의 무게를 계산하고 트럭이 빠지고 새로운 트럭을 넣을 때 무게 때문에 넣지 못하면 무게가 0인 트럭을 넣는다고 생각하였다.
- 큐가 빌 때까지 반복문을 돌며 시간을 1씩 증가시키면 원하는 값이 나온다.

### 고찰 및 개선점
- 다리 위 무게의 변화가 없는 시점을 큐에 추가하여 불필요한 계산 및 반복문 순회가 일어나는 듯하다.
- 새 트럭이 진입할 수 없는 시점부터 가능해지는 시점까지를 계산하여 곧바로 반영할 수 있는 방법이 더 효율적일 것 같다.

## ⭐ 주식가격

[문제 풀이](./ex02_stock_price/Solution.java)

[테스트 케이스](../../../../test/java/group_study/week01/ex02_stock_price/SolutionTest.java)

### 접근 방법 및 시도
- 매초마다 이후 가격이 떨어지지 않을 때까지 걸린 시간을 계산하면 간단히 풀 수 있다.
- 하지만 가격이 계속 오르기만 하는 최악의 경우 C(n-1, 2)번의 경우의 수가 나오고 이는 시간복잡도 O(n^2)을 의미한다.
- n이 최대 100_000이므로 시간복잡도가 낮은 다른 방법을 고려해본다.

### 아이디어 및 풀이
- 문제가 되는 것은 한 시점에서 가격이 떨어지지 않는 구간을 찾을 때 중간 상태를 저장하지 않아 다음 시점에서 구간을 찾을 때 중복 검사가 이루어진다는 점이다.
- 가격이 떨어진다면 떨어진 가격 기준으로 그 가격 초과인 이전 시점들의 구간을 확정할 수 있다.
- 더 작은 가격이 나타나지 않아 가격이 결정되지 않은 인덱스들을 Stack에 넣는다.

### 고찰 및 개선점
- 이중 반복문을 통한 풀이로는 간단히 해결할 수는 있었지만 큰 입력 시 효율성이 문제가 되었다.
- 스택을 이용한 풀이는 아이디어를 생각하는 데 오랜 시간이 걸렸고, 끝내 생각나지 않아 다른 사람의 풀이 아이디어를 참고하고 구현은 직접 하였다.
- 직관적인 구현에는 익숙하나 아이디어를 떠올리고 구체화하는 능력이 아직 부족해 연습이 더 필요할 것 같다.
